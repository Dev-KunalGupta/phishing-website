# PHISHING FRAUD DETECTION USING ENSEMBLE MACHINE LEARNING TECHNIQUES: A HYBRID APPROACH

-> This project is a highly sophisticated cybersecurity system containing explainable AI Threat Intelligence Platform, not just a basic phishing detector.

The Architecture & Workflow Pipeline :- 
The system is built on a Flask backend and follows a 5-step end-to-end data pipeline. When a user submits a URL or uploads a QR code, the following sequence occurs:

Step 1: Input Ingestion (Web & Quishing Defense)
Direct URL: The user enters a URL on the web interface.
QR Code (Quishing): The user uploads a QR image. The system uses Computer Vision (OpenCV) to visually decode the image matrix and extract the hidden URL.
Step 2: The Feature Extraction Engine (feature_extractor.py)
Instead of blindly feeding the URL to black-box ML, the URL is mathematically dissected into data points:

Lexical Analysis: Counts lengths, subdirectories, HTTP/HTTPS usage, and suspicious symbols (@, hyphens).
Keyword & Threat Matching: Looks for manipulative words like "login" or "secure", and checks for risky Top Level Domains (e.g., .xyz, .tk).
Mathematical Entropy: Calculates the randomness of the characters in the domain. High entropy means the domain was likely generated by a botbot algorithm.
Reputation Check: Cross-references the domain against an internal database of the Top 1 Million Legitimate Sites.
Step 3: Dual-Core Analysis (The Hybrid Intelligence)
The extracted features are independently analyzed by two separate "brains":

AI Machine Learning Model (ml_detector.py): The data goes into a pre-trained XGBoost Model. Based on hundreds of thousands of past malicious URLs, it outputs a raw mathematical probability that the URL is a threat.
Expert Rule Engine (rule_engine.py): A strict, deterministic algorithm built on cybersecurity best practices. If a site uses an IP address instead of a domain name paired with a word like "bank", the system immediately flags it for maximum severity, bypassing AI uncertainty.
Step 4: The Hybrid Risk Calculator (risk_calculator.py)
This is the master controller. It merges the ML Probability Score and the Rule-Based Severity Score.

Dynamic Weighting: It adjusts its trust. If a site is mathematically safe but hits a critical rule (like an exposed IP address), the rule engine overrides the ML. If passing the Top 1 Million DB check with HTTPS, it overrides to "Safe".
Output: Returns a Final Risk Percentage (0-100%), a Confidence Score, and heavily categorizes the vector into Safe, Suspicious, or Phishing.
Step 5: Explainable AI & Reporting (explanation_engine.py)
Because modern cybersecurity demands transparency, the application parses the risk factors and generates human-readable explanations (e.g., "The domain appears randomly generated" or "The URL uses an IP address instead of a domain name"). Users can dynamically export this threat intelligence natively as a downloadable PDF report.
